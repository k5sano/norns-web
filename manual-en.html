norns-web manual

An emulator that runs monome norns Lua scripts in the browser. Install scripts from norns.community and play with them, or write your own and try them out.

01Getting started

  1. When the page opens, the sample script step (an 8-step sequencer) starts automatically.
  2. Click anywhere on the page once to hear it. Browsers keep pages silent until you interact with them. The button at the top right reads “SOUND ON” (green) while audio is running.
  3. Open the “Library” tab on the right, pick a script from norns.community and press “Install”. It is fetched and started right away.

It runs in desktop Chrome, Edge, Safari and Firefox. Phones work too, but encoders and the grid are easier to use on a computer. Connecting a hardware grid needs desktop Chrome or Edge. The “日本語 / English” button at the top right switches the interface language.

02The screen

DEVICE (TOP LEFT)The 128×64 screen, keys K1–K3, encoders E1–E3 and the MENU button.
CONTROLLERS (BOTTOM LEFT)GRID 128 / ARC 4 / CROW tabs. Tabs the script uses get a yellow dot, and the first one used is shown automatically.
EDITOR (RIGHT)View and edit scripts, run and stop them, MATRON (the log) and the REPL.
LIBRARY (RIGHT)Catalog search, installing, installed projects and audio files.

The indicator at the top right shows the run state: green while running, red after an error. The error itself appears in MATRON.

03Controls

Mouse and touch

  • Keys: the script sees a press while you hold the key and a release when you let go.
  • Encoders: drag up and down (or left and right) on a knob to turn it. The mouse wheel also works, and so do the arrow keys once the knob is focused.
  • MENU: same as a short K1 press; opens and closes the system menu.

Keyboard

While you are typing in the editor or another text field, these keys type text instead of operating the device.

04System menu

A short K1 press (or MENU) opens the menu; press again to go back to the script. If you hold K1 while using another key or encoder, the menu stays closed and the script receives K1 instead. E1 switches pages.

PageUse
MIXE2 selects a channel (out / eng / cut / rev), E3 changes its level.
TAPENot available in this version.
HOMEE2 selects, K3 confirms. SELECT starts a script from dust/code, SYSTEM restarts the current one, SLEEP blanks the screen. K2 goes back.
PARAMETERSE2 selects, E3 changes the value. Trigger, on/off, file and text parameters use K3.

05Installing scripts

From the catalog

The lower half of the “Library” tab is the norns.community catalog. Search by name, author or tag, and filter by verified, softcut, grid, arc, crow and more.

  • Install: fetches the script straight from GitHub into your browser and starts it. Git submodules come along, and projects the script depends on are installed too.
  • verified: scripts that started without errors in our tests. Scripts without the label may still work.
  • Chips: green engine names are supported; yellow “stand-in” ones play a simple substitute synth. “needs: …” names a required project, and “midi (unsupported)” means MIDI features won't work.
Rate limit　GitHub allows about 60 installs per hour (one per project plus one per submodule). When you hit the limit, the time you can retry is shown.

Managing installed projects

The “Installed · dust/code” list lets you run, update and delete projects. Update fetches the latest version from GitHub and discards your edits. Delete needs two presses.

From files

For scripts that are not in the catalog, drop a ZIP or .lua on the box at the top (or click it to choose a file). A ZIP is unpacked into dust/code/<name>/ and the runnable script opens. Audio files (wav / aif / flac / mp3 / ogg and so on) go into dust/audio/, and png files into dust/data/images/.

06Editor and REPL

  • Pick a file from dust/code in the drop-down. Edits are saved automatically.
  • ▶ Run (Ctrl/⌘+Enter) starts the current file, ■ Stop stops it. Tab inserts two spaces.
  • + New creates a script called untitledN.
  • Revert restores a bundled sample to its original.

MATRON shows print output and errors. The >> field at the bottom is a REPL: it runs one line of Lua inside the running script.

ExampleResult
engine.hz(440)Plays one note at 440 Hz
params:get('clock_tempo')Shows the current tempo
params:set('clock_tempo', 140)Changes the tempo
tab.print(params.lookup)Lists parameter IDs

07grid · arc · crow

GRID 128

Clicking or tapping the 16×8 pads calls the script's g.key(x, y, z). Several fingers can press at once. To use a real grid, see the next section.

ARC 4

Drag around the outside of a ring for a.delta(n, d), press the center knob for a.key(n, z). The mouse wheel turns rings too.

CROW

  • OUT 1–4: bars show the output voltage (−5 to +10 V).
  • IN 1 / IN 2: sliders set the input voltage. The “5V” button is a gate that stays at 5 V while held.
  • Listen: plays OUT 1 as pitch (V/oct) and OUT 2 as level (VCA).

crow.ii (i2c devices) and scripts that run on crow itself (crow.loadscript and the like) are ignored.

08Hardware grid

A real monome grid can be connected over USB and used as the emulator's grid. This needs desktop Chrome or Edge.

  1. Quit serialosc or any other software that is using the grid.
  2. Press “Connect USB grid” in the GRID 128 tab and choose the grid from the list.
  3. Once it shows “connected”, keys and LEDs are linked to the script.

Models and protocols

SettingFor
Auto-detectUses mext if the grid answers, otherwise series.
mextGrids from 2011 on. The size is detected automatically.
seriesmonome 64 / 128 / 256 from 2007–2010. Choose the size yourself.
40hThe 2006 40h and arduinome (choose 57600 baud).

A 256 uses its top 16×8. If you place the grid with the cable on the other side, set rotation to 180°.

Brightness steps and thresholds

Scripts set LED brightness as one of 16 levels, 0–15. You decide which levels light up, and how brightly, to suit your grid.

  • 16 levels: for varibright grids; levels are sent as they are.
  • 4 steps: set the level from which steps 1–3 (dim, mid, bright) light. The value sent for each step (5 / 10 / 15 by default) can be changed too.
  • On / off only: for early mono grids. Set one level from which LEDs turn on.
0123 4567 891011 12131415

Default 4-step mapping: 0–3 off, 4–7 dim, 8–11 mid, 12–15 bright.

The “Mapping” row in the settings shows what each level does with the current settings. Holding “Hold for test pattern” shows levels 0–15 from the leftmost column of the grid, so you can see which column starts to light and adjust. “Show the same steps on the on-screen grid” makes the on-screen grid match the hardware.

Grid not in the list?　Early grids use an FTDI chip and may need the FTDI driver on your computer. macOS includes it.

09Sound and softcut

Engines

EngineStatus
PolyPercSupported (hz amp cutoff release pw gain pan)
TestSineSupported
PolySub / MollyThePolySimplified; the sound is an approximation.
OthersSuperCollider engines are not implemented. Commands that set a pitch play a stand-in percussive sound.

softcut

6 voices and 2 buffers (about 87 seconds each), with rate, loops, crossfades, recording and overdub, filters, voice-to-voice routing, position polling, waveform rendering and reading and writing audio files.

AUDIO IN

“AUDIO IN” below the device chooses what softcut records. “Test tone” is a simple arpeggio; audio files you put in dust/audio can also loop as the input. Microphone input is not supported.

Reverb and compressor (on / off and amount) and the amp_in / amp_out polls are also available.

10Compatibility

About three quarters of the catalog starts without errors. The usual reasons a script doesn't:

  • It relies on parameters that a SuperCollider engine adds
  • It requires MIDI devices
  • It uses the network or OS commands
  • It expects audio or preset files to be in dust already

Available libraries

util tabutil controlspec musicutil sequins lattice lfo reflection pattern_time er formatters ui graph filtergraph envgraph voice fileselect textentry listselect cjson and more. include and require load files from dust/code and these libraries.

Not supported

MIDI, crow.ii, tape, microphone input, OSC and mods. Calling them doesn't raise errors; the calls are ignored.

11Where data is kept

Installed scripts, your edits, audio files, psets and so on are all stored in your browser (IndexedDB). Nothing is sent to a server.

  • Another browser or device starts from scratch.
  • If you send the URL to a friend, they won't see your data.
  • To reset everything, delete this site's data in your browser settings.

12Troubleshooting

ProblemWhat to check
No soundIs the top-right button “SOUND ON” (green)? If it says “SOUND OFF”, click it. On iPhone / iPad the silent switch can mute it. Also check your computer's output device and the MIX page levels. Scripts that use engines other than PolyPerc may play a stand-in sound or nothing.
The indicator turned redRead the error in MATRON. include: … not found means a file or another project is missing.
Install failsEither the rate limit (about 60 per hour) or a network problem. Try again after the time shown.
Things stopped movingRestart with ■ Stop → ▶ Run. Infinite loops are stopped automatically and MATRON shows “timeout”.
The hardware grid won't connectAre you in Chrome / Edge? Did you quit serialosc? For older grids, try choosing the protocol and size by hand.
